# calendar-sync

Загрузи скилл `calendar-sync` и выполни обновление календаря в Obsidian.

**Source of truth:** `skills/calendar-sync/SKILL.md`

## Аргументы

| Аргумент | Действие |
|---|---|
| _(пусто)_ | `~/.local/bin/calendar-sync.py --only all` |
| `relogin` | `~/.local/bin/calendar-sync.py --only all --relogin` — открыть окно, попросить пользователя залогиниться, дождаться `LOGIN_READY`, затем повторить обычный запуск |
| `holidays` | `~/.local/bin/calendar-sync.py --only holidays` |
| `events` | `~/.local/bin/calendar-sync.py --only events` |
| `dry-run` | добавить `--dry-run` к любому из вариантов выше |

## Порядок действий

1. Загрузить скилл `calendar-sync` (детали, коды выхода, разбор ошибок — там).
2. Выполнить соответствующий запуск через Bash.
3. Разобрать код выхода: `0` — успех, `1` — ошибка/самопроверка, `2` — нужен вход
   в Confluence (→ `relogin`), `3` — нет данных (ничего не перезаписывать).
4. При успехе — проверить парность маркеров и статус-блок в `Маппинг.md`, выдать
   короткую сводку: сколько событий и праздников, что изменилось.

## Запреты

- **Не выдумывать данные.** Ни одного события, праздника или даты «по памяти» —
  только то, что реально вернул скрипт/источник. Пустой ответ = пусто, а не повод
  досочинить.
- **При `exit 3` (и `exit 1`) ничего не перезаписывать** — ни вручную, ни повторным
  запуском с `--force`. Сначала разобраться, почему источник пуст/сломан.
- Не менять содержимое заметок вне маркеров `<!-- calendar-sync:begin/end -->`.
- Не коммитить изменения в git и не трогать другие страницы vault.
