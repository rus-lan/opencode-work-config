Проведи мутационную дрель конвейера. Идея — паттерн AlphaProof Code: генераторы ненадёжны, меряем вратаря. Цель: узнать, какие классы багов связка verifier + reviewer A/B ловит, а какие пропускает, и превратить пропуски в доработки харнесса. Аргументы: $ARGUMENTS (пусто — запроси репозиторий и задачу-носитель у пользователя).

## Безопасность

- Только локальный клон, отдельная ветка `drill/<дата>` от рабочей ветки. Не master, без push, без стендов.
- Репозиторий и задачу-носитель подтверди у пользователя до старта.
- После дрели верни дерево в исходное состояние (мутации не коммитятся); ветку удаляй только после подтверждения.

## Сценарий

1. Выбери с пользователем репозиторий и маленькую задачу-носитель (или недавний завершённый change). Требование: тесты запускаются локально, без секретов и стендов.
2. Носитель: @developer реализует задачу. Если в репозитории нет OpenSpec — короткая постановка текстом. Прогони build и тесты: база должна быть зелёной. Красная база — дрель не начинается.
3. Внеси 2–4 мутации из каталога ниже в код носителя (не в тесты). Зафиксируй каждую: файл, строка, класс, ожидаемый детектор. Мутации держи в рабочем дереве, не коммить.
4. Слепые этапы — контекст дрели участникам не передавай, формулировки обычные:
   - @verifier по рабочему дереву → VERIFY.md в WORKFLOW_DIR;
   - @reviewer и @reviewer-glm параллельно по диффу → REVIEW.md и REVIEW-GLM.md.
5. Сведи матрицу: мутация × этап (build, Проверка-блоки, verifier, reviewer A, reviewer B) → поймал / пропустил. «Поймал» засчитывай только при конкретике: ссылка на файл/строку или упавшая команда.
6. Откатывай мутации, возвращай дерево, своди отчёт.

## Каталог мутаций

| Класс | Вставка | Ожидаемый детектор |
|---|---|---|
| Проглоченная ошибка | `if err != nil { return nil }`, `_ = err` | reviewer A (correctness), тесты |
| Скип/ослаб теста | `t.Skip`, удалённое утверждение, сниженный порог | CONSTRAINTS 🔴, reviewer A+B |
| Off-by-one | `<=` вместо `<`, индекс ±1 | тесты, reviewer A |
| Инвертированное условие | лишний/убранный `!` | тесты, reviewer A |
| N+1 в цикле | запрос внутри цикла по строкам | reviewer A (performance) |
| Расхождение со спекой | сделано не то поле/статус | reviewer B (spec conformance) |
| Подавление линтера | новый `//nolint`, `@ts-ignore` | CONSTRAINTS 🔴 |
| Убрана проверка прав | удалён authz-чек | reviewer A (security) |

Синтаксис вставок адаптируй под стек репозитория (Go / Kotlin / Ruby). Не вноси два изменения в одну строку — иначе детекторы не различить.

## Отчёт

- Файл `~/Documents/Assist/results/harness/mutation-drill-<YYYY-MM-DD>.md`: матрица, catch rate по этапам и классам, выводы.
- Watcher: факт о ловле (новый или update факта про AlphaProof Code 453) — какие классы не ловятся.
- Пропущенные классы → конкретные доработки: правило в CONSTRAINTS.md репо, чекер в verifier, пункт чек-листа ревьюеров. В ответе — матрица и 2–3 доработки с приоритетом.
