Разбери сессию: $ARGUMENTS (пусто = только что завершённая / текущая).

Цель — не отчёт, а изменения. Сессия, которая ничего не изменила в харнессе, систему не улучшила.

## 1. Собери сигналы

Источники по убыванию надёжности:

1. **Телеметрия.** `~/Documents/ECOM/mcps/duck-harness/bin/duck-harness --snapshot=false`
   (MCP-сервер падает на снапшоте — не использовать). Колонка времени в `h.tool_calls` называется
   `at` (зарезервированное слово — не годится без кавычек), в `h.sessions` — `created_at`.
   Стартовый запрос:

   ```bash
   D=~/Documents/ECOM/mcps/duck-harness/bin/duck-harness
   $D --snapshot=false --format tsv --sql "select session_id, title, model_id, created_at,
     tokens_input+tokens_output tk from h.sessions order by created_at desc limit 3"
   $D --snapshot=false --format tsv --sql "select tool, status, count(*) n, max(latency_ms) ms,
     any_value(error) err from h.tool_calls where session_id='<id>' group by 1,2 order by n desc"
   ```

   Схема вьюх и разбор — скилл `harness-analytics`.
2. **Сигналы плагина.** `~/.local/share/opencode/retro/sessions.jsonl` — плагин `session-retro` пишет
   дельту на каждый `session.idle`: вызовы, разбивка по тулам, ошибки, повторы «тул + аргумент»,
   запросы прав с ответом (`once` / `always` / `reject`). Есть то, чего нет в БД: история решений по правам.
   `tail -5 ~/.local/share/opencode/retro/sessions.jsonl`.
3. **Диалог.** Повторные вызовы одной пары «тул + аргумент», отказы permission, откаты правок,
   уточняющие вопросы пользователю, срабатывания marathon-reminder (40 вызовов), ошибки MCP.
   Отдельно — **новые «always»**: если в сессии пользователь разрешил что-то навсегда, это правило
   попало в `oc.permission` и теперь действует молча. Такие правила разбирает `/perms`, не ретро.

Чего не знаешь — пиши «нет данных». Не реконструируй цифры по памяти.

## 2. Разложи по трём корзинам

| корзина | признак | куда идёт |
|---|---|---|
| знание | не знал путь, имя тула, граблю | `watcher_save` (kind/sensitivity обязательны) |
| ограничение | ошибался механически: `cd X && …`, edit без read, секреты, марафон | плагин `harness-guards` / permissions — отдельной задачей; новые «always» → `/perms` |
| инструкция | правило нарушалось или его не было | `AGENTS.md`, скилл, команда |

Ошибку, которую можно запретить кодом, в инструкцию не писать — текст её не остановит.

## 3. Запиши файл

`~/Documents/Assist/results/harness/retro-<YYYY-MM-DD>.md` (несколько ретро за день — `-2`, `-3`).
Формат — как в `edit-errors-2026-11-10.md`: источник с параметрами запроса, таблица сигналов,
раздел «вывод-решение».

```markdown
# Ретро сессии <дата> — <тема>

Сессия: <session_id>. Модель: <модель>. Вызовов: N. Токенов: N. Ошибок: N.
Источник: `h.sessions where ...`.

## Сигналы

| сигнал | шт | комментарий |
|---|---:|---|

## Три корзины

- знание → <что сохранил, id факта или «нет»>
- ограничение → <что предложить, задача или «нет»>
- инструкция → <что поправил, файл:строка или «нет»>

## Вывод-решение

<что меняем / что осознанно не меняем и почему>

## Метрика проверки

<какая цифра через 5–10 сессий покажет, что правка сработала>
```

## 4. Примени в этой же сессии

Не больше двух правок: `watcher_save` для знаний и точечный `edit` для инструкций.
Ограничения только фиксируй как предложение — плагин правится отдельной задачей.

## 5. Ответь коротко

1–3 находки, что изменил, какая метрика покажет эффект. Если ни одного артефакта не появилось —
скажи прямо, что сессия прошла без улучшения.

Раз в ~10 файлов `retro-*.md` предложи `/health`: накопленные ретро дают паттерны, которых не видно
по одной сессии.
