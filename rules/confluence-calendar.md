# Confluence — календарь (Team Calendars)

## Когда применять
Когда на странице Confluence есть макрос календаря и нужно получить сами события (название, начало, конец, к кому относится). MCP-инструменты Confluence (`get_page`, `search`, `get_attachments`, `get_page_children`) события календаря НЕ отдают — только сам макрос.

## Что отдаёт страница и чего в ней нет
- `get_page` в raw storage вернёт только макрос `calendar` со списком UUID календарей.
- Вложений (`.ics`) и дочерних страниц у такой страницы, как правило, нет — не тратить время на их поиск.
- **UUID из макроса — это не `subCalendarId`.** Не подставлять их в `events.json` как `subCalendarId` без проверки.
- Статические таблицы отпусков на смежных страницах — это НЕ события календаря. Не смешивать их с событиями макроса.

## Авторизация
- Calendar REST (`/rest/calendar-services/...`) требует авторизованной сессии Confluence. Bearer-токен MCP-шлюза для него не работает (401/404).
- MCP Playwright запускается `--headless --isolated`: видимого окна нет, cookies не сохраняются. Для ручного логина поднимать ОТДЕЛЬНЫЙ headful-Chromium скриптом на `DISPLAY` графической сессии.
- Логин выполняет пользователь сам. Пароли не вводить, SSO не обходить.
- Использовать `chromium.launchPersistentContext(<profileDir>, { headless: false })` — сессия переживает перезапуск, повторный логин не нужен (в логе `ALREADY_LOGGED_IN`).
- Признак авторизации: есть cookie `JSESSIONID` и URL не содержит `login.action`.

## REST: рабочий запрос
```
GET /rest/calendar-services/1.0/calendar/events.json
    ?subCalendarId=<ID>
    &start=2026-12-01T00:00:00Z
    &end=2028-01-01T00:00:00Z
    &userTimeZoneId=Europe/Moscow
```
Выполнять из авторизованной страницы: `page.evaluate(() => fetch(url, { credentials: 'include' }).then(r => r.text()))`.

## Формат дат — главная ловушка
| `start` / `end` | Результат |
|---|---|
| `2026-12-01T00:00:00Z` | **200 + массив `events`** ✅ |
| `2026-12-01T00:00:00.000Z` | 500 `Invalid format: ... malformed at ".000Z"` |
| `2026-12-01` | 500 `... is too short` |
| `1761955200000` (epoch ms) | 500 `malformed at "0000"` |
| `1796083200` (epoch sec) | 500 `malformed at "0"` |

Правило: **ISO-8601, секунды, суффикс `Z`, без миллисекунд.** Если REST отвечает 500 с `Invalid format` — это формат даты, а не права и не авторизация.

## Список календарей
`GET /rest/calendar-services/1.0/calendar/subcalendars.json` → дерево (`payload` / `childSubCalendars`); рекурсивно собрать все `subCalendar.id` и `name`.

Ограничение: список содержит только доступные учётке подкалендари. Календари, чьи UUID стоят в макросе, могут в нём отсутствовать — `events.json` всё равно резолвит их по id.

## `{"success":true}` без `events` — это пусто, а не сбой
Тело из ~16 байт `{"success":true}` = событий за период нет либо нет прав на этот календарь. Не трактовать как ошибку транспорта.

## Надёжный способ получить события: перехват сети
UI сам запрашивает `events.json` при отрисовке макроса. Значит, если события видны в UI, их можно снять перехватом:
1. Запустить persistent context, повесить `context.on('response', ...)` с фильтром по `/calendar-services|events\.json|ical|\.ics/i`.
2. Открыть страницу календаря, дождаться макроса (`[id*="calendar"]`, `[class*="TeamCalendars"]`), проскроллить к нему, подождать 5 с.
3. Сохранить каждый ответ (url, status, body) — в телах лежат массивы `events`.
4. Расширить диапазон: макрос обычно запрашивает узкое окно (например `2026-09-26 … 2027-01-06`); повторный запрос с широким окном вернёт больше событий.

## Поля события
`title`, `localizedStartDate`, `start`, `end`, `allDay`, `recur`, `eventType`, `subCalendarId`.

«Кому относится» — из `subCalendarId` → `name` подкалендаря (например `Т100 / Отпуска`, `Календарь T102 / Дни рождения`) плюс ФИО из `title`.

## Дедупликация и повторяющиеся события
- Одно событие может прийти из нескольких подкалендарей или из refetch — схлопывать по `(title, start, end)`.
- `recur: YEARLY` (дни рождения) даёт отдельное вхождение в каждом году — это не дубликаты.

## Фолбэк: DOM
Если перехват не дал событий — собрать элементы `.fc-event`, `[class*="event"]`, `[data-event-id]`: `innerText`, `title`, `aria-label`, `data-event-id`. Сохранить скриншот макроса как доказательство отрисовки.

## Чего не делать
- Не полагаться на навигацию по месяцам внутри макроса: стрелка `›` ловится не в том контейнере, заголовок месяца не меняется, новых XHR нет. Расширять диапазон в REST надёжнее.
- Не использовать MCP Playwright для ручного логина — он headless.
- Не подставлять UUID из макроса в `subCalendarId` без проверки.
- Не выдавать статические таблицы смежных страниц за события календаря.
- Не вводить пароли и не обходить SSO.

## Чек-лист
1. `get_page` (raw storage) → есть ли макрос `calendar`, какие UUID.
2. Проверить в UI у пользователя, видны ли события (это отделяет «пусто» от «нет прав через API»).
3. Есть ли `JSESSIONID` в persistent-профиле; иначе headful + ручной логин пользователем.
4. `subcalendars.json` → id + имена.
5. `events.json` с ISO-без-мс на широкий диапазон по каждому id.
6. Перехват сети при отрисовке макроса — основной/подтверждающий источник.
7. Дедупликация, нормализация дат в `DD.MM.YYYY`, группировка по месяцам.
8. В заметке зафиксировать метод получения, рабочий формат дат и что осталось недоступно.
