# GitLab MCP — fallback на локальный клон

## Когда применять

Когда задаче нужны файлы/дерево/код GitLab-репозитория, а MCP-сервер `gitlab` не отдаёт результат: ошибка авторизации (401/403), `aborted`/timeout/обрыв сессии, пустой или обрезанный ответ, упор в лимит рекурсии или размера, слишком большой репозиторий.

## Что делать

1. Не ретраить MCP бесконечно: максимум 1–2 попытки, затем сразу fallback.
2. Клонировать репозиторий локально в подпапку `source/` рабочего проекта:

   ```bash
   mkdir -p source
   git clone https://git.ecom.tech/<group>/<project>.git source/<project>
   ```

   Если HTTPS требует авторизации и падает — попробовать SSH:

   ```bash
   git clone git@git.ecom.tech:<group>/<project>.git source/<project>
   ```

   Для больших репозиториев — `--depth 1` (или `--filter=blob:none`), для конкретной ветки — `--branch <name>`. Нужна нестандартная ветка — `git fetch origin <branch> && git checkout <branch>`.
3. Обязательно добавить `source/` в `.gitignore` целевого проекта: создать файл, если его нет, иначе дописать строку, НЕ затирая существующее содержимое.
4. Дальше работать с клоном локально (`git ls-files`, `rg`, `cat`, `tree`) — это быстрее и не раздувает контекст ответами MCP.
5. В отчёте указать: путь к клону, ветку, commit hash и дату.

## Запрещено

- Коммитить или пушить что-либо из клона без явного разрешения пользователя.
- Клонировать в каталоги проекта вне `source/`.
- Изменять содержимое клона: это read-only источник методики/кода.
- Обходить авторизацию, подбирать креды, отключать проверки TLS.
