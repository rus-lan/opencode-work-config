# Эталон формата: комментарий «Результаты валидации»

Шаблон-образец, а не подставляемый файл: тело собирает
`report.render_validation_comment(run_dir)`, а `publish.build_comment`
дописывает в первую строку маркер идемпотентности
`task-readiness-review:validation:<TASK-KEY>` (в угловых скобках-комментариях
HTML, чтобы не рендериться в Jira).

* `ref` записи в `state.published[]`: `<TASK-KEY>#validation`
* файл тела в каталоге прогона: `jira-validation.md`
* пакет ручной публикации: `actions/jira-validation.md`

Правила формата:

* только про готовность: вердикт, пробелы, гигиена полей, как перегенерировать;
* ни одного числа SP, диапазона или записи провенанса — это второй комментарий;
* блокирующие пробелы (REQUIRED) — с адресатом и «где искать»;
* «что уточнить» (RECOMMENDED) — до 8 пунктов, остальное строкой «и ещё N»;
* гигиена полей — провалы правил `TPL-*`, каждый пункт печатается один раз;
* объём — до ~40 строк. Обрезка по `MAX_COMMENT_CHARS` здесь срабатывать не
  должна: если срабатывает — это баг формата, а не длинный текст.

---

## Результаты валидации <TASK-KEY> — <заголовок задачи>

**Вердикт: <OK|WARN|BLOCKED>** — <причина одной строкой>
Понято как: <вид работ по заголовку и тексту> («<цитата из задачи>»)

Строка «Понято как» — ось `work_intent` из `validation.json` (первый сигнал).
Она не влияет на вердикт и не содержит чисел: это ответ на вопрос «что здесь
делается», чтобы читатель не угадывал по заголовку. Строки нет, если ось не
посчитана (артефакты до версии правил 4).

### Блокирующие пробелы (<N>)

- **<RULE-ID>** (<роль>) — <что нужно уточнить>. Где искать: <раздел / источник>

Если блокирующих нет, вместо пунктов одна строка:

    нет — блокирующих пробелов нет

### Что уточнить (<N>)

- **<RULE-ID>** (<роль>) — <что нужно уточнить>
- и ещё <N> — см. полный список

Если замечаний нет, вместо пунктов одна строка:

    нечего — замечаний нет

### Гигиена полей (<N>)

- **<TPL-ID>** — <сообщение проверки>

Блок печатается только когда провалы правил `TPL-*` есть в `validation.json`.

Полный отчёт: `runs/<TASK-KEY>/<RUN-ID>/report.md` · пробелы: `runs/<TASK-KEY>/<RUN-ID>/validation.json`
Перегенерировать: `/task-readiness-review check --task <TASK-KEY>`
