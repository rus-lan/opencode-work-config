# Шаблон: событие Kafka (топик × направление)

Назначение шаблона: описать обработку одного топика в одном направлении.
Файл-экземпляр: `services/<svc>/logic/events/<topic>-<direction>.md`. Если
сервис и публикует, и читает один топик — это два разных файла.

## Фиксированные секции (порядок менять запрещено)

1. Топик и направление (обязательно)
2. Схема (обязательно)
3. Условия публикации/обработки (обязательно)
4. Логика обработки (обязательно)
5. Гарантии доставки (обязательно)
6. DLQ и ретраи (обязательно)

## Скелет файла

````markdown
# {{topic}} ({{direction}})

## 1. Топик и направление
Топик: `{{topic}}`
Направление: `{{direction}}`

## 2. Схема
Схема: [{{schema-file-name}}](../../contracts/{{schema-file-name}})

## 3. Условия публикации/обработки
{{trigger-condition}}

## 4. Логика обработки
1. {{step-1}}
2. {{step-2}}

## 5. Гарантии доставки
{{delivery-guarantee}}

## 6. DLQ и ретраи
{{dlq-and-retries}}

<!-- EXTENSIONS -->
<!-- Опциональные секции добавляются здесь и только здесь. Порядок фиксированных секций выше менять запрещено. -->
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{topic}}` | конфиг/код продюсера или консьюмера | имя топика дословно как в брокере | 1 строка | — |
| `{{direction}}` | код (продюсер/консьюмер) | закрытый список: `consume` \| `produce` | закрытый список | — |
| `{{schema-file-name}}` | файл в `services/<svc>/contracts/` (JSON schema топика) | имя файла | 1 строка | `N/A (нет данных в источнике)` |
| `{{trigger-condition}}` | код: условие, при котором сообщение публикуется/обрабатывается | 1–2 предложения | ≤ 300 символов | `N/A (нет данных в источнике)` |
| `{{step-N}}` | код обработчика/продюсера, построчно | 1 шаг = 1 действие, императив | ≤ 160 символов на шаг | `N/A (нет данных в источнике)` |
| `{{delivery-guarantee}}` | конфиг брокера/клиента (acks, конфиг консьюмер-группы) | закрытый список: `at-least-once` \| `at-most-once` \| `exactly-once` \| `неизвестно` | закрытый список | `неизвестно` |
| `{{dlq-and-retries}}` | конфиг клиента Kafka | закрытая структура: наличие DLQ (`да`/`нет`) + число ретраев (число или `неизвестно`) | ≤ 200 символов | `N/A (нет данных в источнике)` |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–6, ничего не переставлено.
- [ ] Front-matter содержит `id: <svc>-<topic>-<direction>`, `type: logic-event`, `service: <svc>`.
- [ ] `{{direction}}` — строго `consume` или `produce`, не оба в одном файле.
- [ ] `{{delivery-guarantee}}` — значение строго из закрытого списка.
- [ ] Ссылка на схему в секции 2 указывает на существующий файл в `contracts/`.
- [ ] Файл не превышает 400 строк.
- [ ] Файл добавлен в `index.yaml` секции `services/`.

## Как используется скиллом

- check-id: DEP-02
- роль в проверке: для топика описание логики — это схема, условия публикации/обработки, гарантии доставки и DLQ/ретраи. Без них нельзя оценить риск обратной совместимости события, поэтому DEP-02 фиксирует пробел до оценки.
