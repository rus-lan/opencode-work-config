# Шаблон: паспорт сервиса

Назначение шаблона: назначение сервиса, стек, владельцы, зависимости,
критичные переменные окружения. Файл-экземпляр:
`services/<svc>/overview.md`, один на сервис.

## Фиксированные секции (порядок менять запрещено)

1. Назначение сервиса (обязательно)
2. Стек (обязательно)
3. Владельцы (обязательно)
4. Репозиторий (обязательно)
5. Зависимости (обязательно)
6. Переменные окружения (обязательно)

## Скелет файла

````markdown

## 1. Назначение сервиса
{{purpose}}

{{stack}}

## 3. Владельцы

## 6. Переменные окружения
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{service-name}}` | имя каталога в `services/` | kebab-case | ≤ 40 символов | — |
| `{{purpose}}` | Confluence / README репозитория сервиса | 1–2 абзаца | ≤ 500 символов | `N/A (нет данных в источнике)` |
| `{{stack}}` | манифесты репозитория (`go.mod`, `package.json`, letsgo-спека) | закрытый список: `go-legacy` \| `letsgo` \| `nodejs` \| `vue` \| `react`, + версия | 1 строка на технологию | `N/A (нет данных в источнике)` |
| `{{owner-role-1}}` / `{{owner-1}}` | CODEOWNERS репозитория / Confluence | роль (`tech lead`, `команда`) + имя/команда | ≤ 80 символов | `N/A (нет данных в источнике)` |
| `{{repo-path}}` | GitLab | путь вида `ecom/dev/is/mm/erm/erm-backend` | 1 строка | `N/A (нет данных в источнике)` |
| `{{dependency-1-name}}` / `-direction` / `-protocol` | код (клиенты, конфиги), контракты | направление — закрытый список: `inbound` \| `outbound` \| `bidirectional`; протокол — `http` \| `grpc` \| `kafka` \| `other` | 1 строка на зависимость | `N/A (нет данных в источнике)` |
| `{{env-1-name}}` / `-purpose` / `-is-secret` | `.env.example`, deployment-манифесты | секрет — `да` \| `нет`; значения секретов сюда не переносятся, только имя и назначение | 1 строка на переменную | `N/A (нет данных в источнике)` |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–6, ничего не переставлено.
- [ ] Front-matter содержит `id: <svc>-overview`, `type: service-overview`, `service: <svc>`.
- [ ] `{{stack}}` использует только значения из закрытого списка технологий.
- [ ] В таблице переменных окружения нет фактических значений секретов, только имя/назначение/флаг.
- [ ] `{{dependency-1-direction}}` и `{{dependency-1-protocol}}` — только из закрытых списков.
- [ ] Файл не превышает 400 строк.
- [ ] Файл добавлен в `index.yaml` секции `services/`.

## Как используется скиллом

- check-id: DEP-01
- роль в проверке: раздел `service-overview` — ровно то, что ищет DEP-01 для затронутого сервиса: назначение, стек, владельцы, зависимости, переменные окружения. Без него неизвестны границы изменений, а зависимость остаётся неописанной — пробел фиксируется, а не заполняется догадкой.
