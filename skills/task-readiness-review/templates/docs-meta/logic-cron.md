# Шаблон: один крон

Назначение шаблона: описать один фоновый job по расписанию. Файл-экземпляр:
`services/<svc>/logic/crons/<job-name>.md`, один файл на один job.

## Фиксированные секции (порядок менять запрещено)

1. Расписание (обязательно)
2. Назначение (обязательно)
3. Логика обработки (обязательно)
4. Побочные эффекты (обязательно)
5. Идемпотентность (обязательно)
6. Действия при сбое (обязательно)

## Скелет файла

````markdown
# {{job-name}}

## 1. Расписание
`{{schedule}}`

## 2. Назначение
{{purpose}}

## 3. Логика обработки
1. {{step-1}}
2. {{step-2}}

## 4. Побочные эффекты

| Тип | Что происходит |
|---|---|
| {{effect-1-type}} | {{effect-1-description}} |

## 5. Идемпотентность
{{idempotency}}

## 6. Действия при сбое
{{failure-runbook-link}}

<!-- EXTENSIONS -->
<!-- Опциональные секции добавляются здесь и только здесь. Порядок фиксированных секций выше менять запрещено. -->
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{job-name}}` | имя job в коде/конфиге шедулера | kebab-case, простой английский | ≤ 40 символов | — |
| `{{schedule}}` | конфиг шедулера | cron-выражение как в конфиге, дословно | 1 строка | `N/A (нет данных в источнике)` |
| `{{purpose}}` | код job, Jira-задача создания | 1 строка | ≤ 120 символов | `N/A (нет данных в источнике)` |
| `{{step-N}}` | код job, построчно в порядке выполнения | 1 шаг = 1 действие, императив | ≤ 160 символов на шаг | `N/A (нет данных в источнике)` |
| `{{effect-1-type}}` / `-description` | код (запросы к БД, публикация в Kafka, вызовы других сервисов) | тип — закрытый список: `db` \| `kafka` \| `external-call` \| `cache` | ≤ 160 символов на описание | `N/A (нет данных в источнике)` |
| `{{idempotency}}` | код (наличие ключа идемпотентности / проверки повторного запуска) | закрытый список: `да` \| `нет` \| `неизвестно` + 1 строка обоснования | ≤ 200 символов | `неизвестно` (никогда не оставлять пустым) |
| `{{failure-runbook-link}}` | существующий файл в `operations/` | markdown-ссылка на runbook либо `N/A (нет данных в источнике)`, если runbook ещё не написан | 1 строка | `N/A (нет данных в источнике)` |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–6, ничего не переставлено.
- [ ] Front-matter содержит `id: <svc>-<job-name>`, `type: logic-cron`, `service: <svc>`.
- [ ] `{{schedule}}` скопировано дословно из конфига, не пересказано словами.
- [ ] `{{idempotency}}` — одно из значений `да / нет / неизвестно`, никогда не пусто.
- [ ] Ссылка в секции 6 (если есть) ведёт на реально существующий файл в `operations/`.
- [ ] Файл не превышает 400 строк.
- [ ] Файл добавлен в `index.yaml` секции `services/`.

## Как используется скиллом

- check-id: DEP-02
- роль в проверке: для джоба описание логики — расписание, шаги, побочные эффекты, идемпотентность и действия при сбое. Незаполненная идемпотентность (`неизвестно`) — отдельный вопрос к SA: от неё зависит, безопасна ли правка и насколько она объёмна.
