# Шаблон: обзор автотестов ИС

Назначение шаблона: где лежит репозиторий автотестов ИС, какие типы тестов
есть, как запустить прогон, где искать шаблоны кода тестов. Файл-экземпляр:
`testing/overview.md`, ровно один на ИС.

## Фиксированные секции (порядок менять запрещено)

1. Репозиторий автотестов (обязательно)
2. Типы автотестов (обязательно)
3. Запуск прогона на стенде (обязательно)
4. Маршрутизация уровней тестирования (обязательно)
5. Шаблоны кода (обязательно)

## Скелет файла

````markdown
# {{is-name}}: автотесты

## 1. Репозиторий автотестов
{{autotests-repo-path}}

## 2. Типы автотестов

| Тип | Где в репозитории | Комментарий |
|---|---|---|
| {{test-type-1}} | {{test-type-1-path}} | {{test-type-1-comment}} |

## 3. Запуск прогона на стенде
{{run-instructions}}

## 4. Маршрутизация уровней тестирования
Регламент: `{{routing-regulation-path}}`

## 5. Шаблоны кода
{{templates-location}}

<!-- EXTENSIONS -->
<!-- Опциональные секции добавляются здесь и только здесь. Порядок фиксированных секций выше менять запрещено. -->
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{autotests-repo-path}}` | GitLab | путь вида `ecom/dev/is/mm/erm/<autotests-repo>` | 1 строка | `N/A (нет данных в источнике)` |
| `{{test-type-1}}` / `-path` / `-comment` | структура репозитория автотестов (Kotlin, in-house фреймворк — детали фреймворка не изобретаются) | тип — закрытый список: `api` \| `ui` \| `kafka` \| `elastic` \| `integration`; путь — относительно корня репо автотестов | ≤ 120 символов на комментарий | `N/A (нет данных в источнике)` |
| `{{run-instructions}}` | README репозитория автотестов, CI-конфиг | 1–2 абзаца, команды в code-span | ≤ 500 символов | `N/A (нет данных в источнике)` |
| `{{routing-regulation-path}}` | общекомандный регламент (файл вне `_docs`, упоминается только как путь) | обычный путь строкой, не markdown-ссылка (регламент вне `_docs`) | 1 строка | `N/A (нет данных в источнике)` |
| `{{templates-location}}` | структура репозитория автотестов | путь к каталогу с базовыми классами/шаблонами Kotlin | 1 строка | `N/A (нет данных в источнике)` |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–5, ничего не переставлено.
- [ ] Front-matter содержит `id: testing-overview`, `type: testing-overview`.
- [ ] `{{test-type-1}}` — только значения из закрытого списка `api/ui/kafka/elastic/integration`.
- [ ] Ссылка на регламент в секции 4 — обычный путь текстом, не markdown-ссылка за пределы `_docs`.
- [ ] Файл не изобретает детали внутреннего Kotlin-фреймворка, которых нет в источнике.
- [ ] Файл не превышает 400 строк.
- [ ] Файл добавлен ровно в один `index.yaml`.

## Как используется скиллом

- check-id: DEP-03
- роль в проверке: DEP-03 ищет раздел `testing-overview` для затронутого контракта: репозиторий автотестов, типы тестов, запуск прогона, маршрутизация уровней. Без него QA оценивает вслепую, и QA-часть оценки выходит с `confidence=low`, а не с придуманной цифрой.
