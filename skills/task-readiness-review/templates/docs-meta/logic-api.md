# Шаблон: одна ручка API

Назначение шаблона: описать одну ручку API — контракт и логику обработки.
Файл-экземпляр: `services/<svc>/logic/api/<verb-resource>.md`, один файл на
одну ручку. Правило имени файла — `_meta/schema.md`, раздел 6.

## Фиксированные секции (порядок менять запрещено)

1. Метод и путь (обязательно)
2. Назначение (обязательно)
3. Вход (обязательно)
4. Выход (обязательно)
5. Ошибки (обязательно)
6. Логика обработки (обязательно)
7. Побочные эффекты (обязательно)
8. Контракт (обязательно)

## Скелет файла

````markdown
# {{method}} {{path}}

## 1. Метод и путь
`{{method}} {{path}}`

## 2. Назначение
{{purpose}}

## 3. Вход

| Параметр | Где | Тип | Обязателен | Описание |
|---|---|---|---|---|
| {{param-1-name}} | {{param-1-location}} | {{param-1-type}} | {{param-1-required}} | {{param-1-description}} |

## 4. Выход

| Поле | Тип | Описание |
|---|---|---|
| {{field-1-name}} | {{field-1-type}} | {{field-1-description}} |

## 5. Ошибки

| Код | Условие |
|---|---|
| {{error-1-code}} | {{error-1-condition}} |

## 6. Логика обработки
1. {{step-1}}
2. {{step-2}}

## 7. Побочные эффекты

| Тип | Что происходит |
|---|---|
| {{effect-1-type}} | {{effect-1-description}} |

## 8. Контракт
Контракт: [{{contract-file-name}}](../../contracts/{{contract-file-name}})
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{method}}` / `{{path}}` | роутинг из `services/<svc>/structure.md` → `{{entrypoint-routing}}`, код | HTTP-метод заглавными + путь как в роутере | 1 строка | — (ручка без метода и пути не создаётся) |
| `{{purpose}}` | код обработчика, Jira-задача создания ручки | 1 строка | ≤ 120 символов | `N/A (нет данных в источнике)` |
| `{{param-1-name}}` / `-location` / `-type` / `-required` / `-description` | контракт (OpenAPI) + код валидации | `location` — закрытый список: `path` \| `query` \| `header` \| `body`; `required` — `да` \| `нет` | 1 строка на параметр | `N/A (нет данных в источнике)` |
| `{{field-1-name}}` / `-type` / `-description` | контракт (OpenAPI) + код сериализации ответа | 1 строка на поле | ≤ 100 символов на описание | `N/A (нет данных в источнике)` |
| `{{error-1-code}}` / `-condition` | код обработки ошибок | код — HTTP-статус или доменный код ошибки как в коде | 1 строка на условие | `N/A (нет данных в источнике)` |
| `{{step-N}}` | код обработчика, построчно в порядке выполнения | 1 шаг = 1 проверяемое действие, императив | ≤ 160 символов на шаг | `N/A (нет данных в источнике)` |
| `{{effect-1-type}}` / `-description` | код (запросы к БД, публикация в Kafka, вызовы других сервисов) | тип — закрытый список: `db` \| `kafka` \| `external-call` \| `cache` | ≤ 160 символов на описание | `N/A (нет данных в источнике)` |
| `{{contract-file-name}}` | файл в `services/<svc>/contracts/`, покрывающий эту ручку | имя файла контракта | 1 строка | `N/A (нет данных в источнике)` — секция 8 тогда содержит только эту строку без ссылки |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–8, ничего не переставлено.
- [ ] Front-matter содержит `id: <svc>-<verb-resource>`, `type: logic-api`, `service: <svc>`.
- [ ] Имя файла = kebab(глагол по таблице метода + ресурс), без параметров пути.
- [ ] Шаги в секции 6 пронумерованы и идут в порядке исполнения кода.
- [ ] Каждый побочный эффект имеет тип строго из закрытого списка.
- [ ] Ссылка на контракт в секции 8 указывает на существующий файл в `contracts/`.
- [ ] Файл не превышает 400 строк.
- [ ] Файл добавлен в `index.yaml` секции `services/`.

## Как используется скиллом

- check-id: DEP-02
- роль в проверке: DEP-02 ищет описание логики затронутого контракта; для ручки это вход, выход, ошибки и ссылка на контракт. Отсутствие — пробел: контракт не проверяем, объём правки неизвестен, поэтому оценка растёт на шаг шкалы (штраф из `gap_rules`).
