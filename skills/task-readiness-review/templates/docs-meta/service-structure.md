# Шаблон: карта кода сервиса

Назначение шаблона: дать LLM карту репозитория без чтения всего кода — где
что лежит и с чего начинать чтение. Файл-экземпляр:
`services/<svc>/structure.md`, один на сервис. Слоты заполняются механически
скиллом `project-map` при сканировании репозитория.

## Фиксированные секции (порядок менять запрещено)

1. Дерево каталогов (обязательно)
2. Точки входа (обязательно)
3. Конфиги, миграции, тесты, контракты (обязательно)
4. Правила структуры (обязательно)

## Скелет файла

````markdown
# {{service-name}}: карта кода

## 1. Дерево каталогов

| Каталог | Назначение (1 строка) |
|---|---|
| {{dir-1-path}} | {{dir-1-purpose}} |

## 2. Точки входа

| Тип | Путь |
|---|---|
| main | {{entrypoint-main}} |
| роутинг | {{entrypoint-routing}} |
| DI / сборка зависимостей | {{entrypoint-di}} |

## 3. Конфиги, миграции, тесты, контракты

| Что | Путь |
|---|---|
| конфиги | {{path-configs}} |
| миграции БД | {{path-migrations}} |
| тесты | {{path-tests}} |
| контракты (исходники) | {{path-contracts-source}} |

## 4. Правила структуры
{{structure-rules}}

<!-- EXTENSIONS -->
````

## Таблица слотов

| Слот | Источник факта | Формат | Лимит | Если факта нет |
|---|---|---|---|---|
| `{{dir-1-path}}` / `{{dir-1-purpose}}` | сканирование репозитория скиллом `project-map` (глубина — только каталоги верхнего и второго уровня) | путь относительно корня репо + 1 строка | ≤ 100 символов на назначение | `N/A (нет данных в источнике)` |
| `{{entrypoint-main}}` | сканирование (`main.go`, `main.py`, `index.ts`, letsgo-манифест) | путь к файлу | 1 строка | `N/A (нет данных в источнике)` |
| `{{entrypoint-routing}}` | сканирование (роутер/контроллер верхнего уровня) | путь к файлу | 1 строка | `N/A (нет данных в источнике)` |
| `{{entrypoint-di}}` | сканирование (wire/fx/DI-контейнер, либо явное «нет DI-контейнера») | путь к файлу либо `нет DI-контейнера` | 1 строка | `N/A (нет данных в источнике)` |
| `{{path-configs}}` / `{{path-migrations}}` / `{{path-tests}}` / `{{path-contracts-source}}` | сканирование по стандартным именам каталогов (`config/`, `migrations/`, `*_test.go`/`tests/`, `api/`, `proto/`) | путь относительно корня репо | 1 строка каждый | `N/A (нет данных в источнике)` |
| `{{structure-rules}}` | тип сервиса из `overview.md` (`{{stack}}`) | для `letsgo` — фиксированная фраза «структура генерируется платформой letsgo, ручные правки вне сгенерированных каталогов»; для остальных — факты о фактической организации кода | ≤ 400 символов | `N/A (нет данных в источнике)` |

## Самопроверка (чек-лист)

- [ ] Секции идут в порядке 1–4, ничего не переставлено.
- [ ] Front-matter содержит `id: <svc>-structure`, `type: service-structure`, `service: <svc>`.
- [ ] Все пути в таблицах — реальные пути в репозитории на момент сканирования (не придуманы).
- [ ] Для `letsgo`-сервисов секция 4 явно ссылается на то, что структура генерируется платформой.
- [ ] Файл не превышает 400 строк (при большом числе каталогов — оставлять только верхние 2 уровня, не листать полное дерево).
- [ ] Файл добавлен в `index.yaml` секции `services/`.

## Как используется скиллом

- check-id: DEP-01 (карта кода)
- роль в проверке: уточняет, где в сервисе точки входа, контракты, миграции и тесты. DEP-01 ищет раздел документации сервиса; паспорт отвечает «что это за сервис», карта кода — «где править». Без карты проверка видит только половину раздела.
