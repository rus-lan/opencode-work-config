# Скоринг feature-toggle (T100)

Порядок вычисления: **Риск поломки → Неопределённость → Оценка → Вычисление**.
Зона проработки SA.

## Процесс

1. При передаче активности и первичном анализе SA определяет объём изменений и
   риски, влияющие на релиз.
2. Если есть опасения — SA формирует черновые задачи и прогоняет их по таблицам ниже.
3. Встреча с командой разработки: определяются возможные проблемы и черновые оценки.
4. После этого весь спринт окончательно оценивается по таблицам.
5. Если фича-тоггл нужен — задачи правятся под нововведения.

## Риск поломки (7 бинарных критериев)

| Подкритерий | 0 | 1 |
|---|---|---|
| Интеграции | Нет | Есть |
| Зона доработок | Один сервис | Несколько сервисов |
| Test coverage | >= 60% | < 60% |
| Исторические сбои | 0 багов за квартал | > 1 бага за квартал |
| Критичность пути | Не меняется user flow | Меняется user flow |
| Наличие алертов | Да | Нет |
| Наличие миграций | Нет | Да |

Сумма по 7 критериям — вход колонки «Риск поломки» таблицы оценки (0–7).

## Неопределённость (5 бинарных критериев)

| Подкритерий | 0 | 1 |
|---|---|---|
| Контракты | Есть спецификации | Нет спецификаций / есть вопросы |
| БД/схемы | Только чтение | Миграции / изменения |
| Интеграции | Внутри ИС | Внешние ИС |
| Кодовая база | Известный модуль | Легаси / новая |
| Сиквел-диаграмма | Есть и актуальна | Нет / устарела |

Сумма по 5 критериям — вход колонки «Неопределённость» (0–5).

## Оценка (8 критериев, шкала 0–5)

| Критерий | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| Размер эпика (Dev+QA) | < 6 SP | 6–12 SP | 13–18 SP | 19–24 SP | 25–30 SP | > 30 SP |
| Задачи | 1–2 задачи на 1 стек | 2–3 задачи | 4–5 задач | 3+ фронт | 3+ бек | > 10 задач |
| Риск поломки | 0 | 1 | 2 | 3 | 4–5 | 6–7 |
| Неопределённость | 0 | 1 | 2 | 3 | 4 | 5 |
| Тесты | Нет | Unit-покрытие | Автотесты | Ручная проверка | Частичный E2E | Полный E2E |
| Интеграции | Нет | 1 внутренняя | 2 внутренние | 1 внешняя | 2+ внешние | Блокирующие |
| Протяжённость | 1–2 дня | Неделя | 1 спринт | 2 спринта | 3+ спринта | Квартал+ |
| Отложенный релиз | Вчера | По готовности | Конец спринта | +1 спринт | +2 спринта | Квартал+ |

Допустимые оценки каждого критерия: 0–5. Итог — сумма восьми оценок (0–40).

## Вычисление

| Итоговые баллы | Решение | Действие |
|---|---|---|
| 0–10 | Не нужен | По старому флоу |
| 11–20 | Рассмотреть | Обсудить на проработке |
| 21–30 | Toggle нужен | Toggle |
| 31+ | Toggle обязателен | Toggle + мониторинг/алерты + дежурные при релизе |

## Как используется скиллом

- `FT-01` (RECOMMENDED): если задача — новый функционал (`issue_type=Feature` или
  метки `feature`/`toggle`/`feature-toggle`), в описании задачи или вложениях
  должен быть приложен скоринг тоггла. Проверка ищет раздел «Feature-toggle» /
  «Скоринг тоггла», таблицы «Риск поломки» и «Неопределённость», либо вложение с
  `toggle`/`scoring` в имени.
- Критерии этого файла в `check.CHECKS` не разворачиваются в отдельные правила:
  скоринг заполняет SA, а движок проверяет только его наличие. Разворачивание
  критериев в отдельные правила — изменение каталога (`RULES_VERSION` и
  `references/validation-rules.md`).
