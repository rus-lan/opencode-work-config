# Confluence MCP: стабильный workflow (выведен 2026-10-09 на реальном инциденте)

## Почему зависает
- Гигантский payload (целая страница в одном update_page) → таск сабагента-обёртки обрывается (дважды подтверждено).
- MCP-шлюз «флапает»: пачки 503 Service Unavailable, затем сам восстанавливается.
- `content_file` не работает: обёртка не имеет доступа к файловой системе.
- Тройные backtick ``` внутри update_page_section «съедаются» markdown-конвертером.

## Правила записи страницы (главное)
1. Декомпозиция ОБЯЗАТЕЛЬНА: сначала «скелет» — `confluence_update_page` (title + вступление + пустые заголовки секций), затем каждая секция отдельным вызовом `confluence_update_page_section` (content_format=markdown, heading_text = точный текст заголовка БЕЗ «##»).
2. Один вызов ≤ ~80–100 строк контента; крупную секцию режь на подразделы.
3. Контент — ТОЛЬКО inline в параметре content. Если контент лежит в файлах — сначала general-агент возвращает текст, потом передавай его в промпт обёртки. Одна страница (лучше — одна секция) = один таск; не пихай две страницы в один таск.
4. Код-блоки: `content_format=storage` и макрос `<ac:structured-macro ac:name="code" ac:schema-version="1"><ac:parameter ac:name="language">text</ac:parameter><ac:plain-text-body><![CDATA[...]]></ac:plain-text-body></ac:structured-macro>`.
5. После каждой записи — `get_page` для верификации; в конце — общий проход по секциям и финальная version.

## Анти-зацикливание и 503
- Максимум 2 попытки на каждый вызов; 3 неудачных вызова ПОДРЯД → СТОП, честный отчёт «что записано / что нет».
- 503 — транзиентный флап: не долбить без пауз; при повторном флапе — вернуться к задаче позже.
- Бюджет неудач на сессию ~10 → сообщить пользователю и искать альтернативный путь (по инструкции оркестратора).
- Таймауты вызовов — тот же флап; не ждать бесконечно.

## Безопасность
- Трогать ТОЛЬКО явно запрошенные page_id; никаких лейблов/комментариев/вложений, если явно не попросили.
- Перед перезаписью убедиться, что страница пустая/заглушка; если там есть контент — согласовать, не затирать.

## Чеклист публикации
1. get_page → пустота? title? version?
2. update_page — скелет.
3. update_page_section × N (по одной секции).
4. get_page — верификация всех секций.
5. Отчёт: URL, финальная version, список секций ✅/❌.

## Как находить и формировать ссылки (ac:link)
- Читай страницу в raw storage (convert_to_markdown=False), чтобы видеть реальную разметку ссылок.
- Находи: голые <a href="https://space.samokat.ru/pages/viewpage.action?pageId=NNNN"> и текстовые pageId=NNNN/голые номера. Трогай только ссылки домена space.samokat.ru.
- Резолвь page_id через get_page (точный title + space_key), не выдумывай названия.
- Форма: <ac:link><ri:page ri:content-title="<title>" ri:space-key="<space>"/></ac:link>; в тексте добавляй [<page_id>] рядом, ничего не удаляя. Экранируй XML-спецсимволы в атрибутах.
- Запись: update_page для компактных страниц; для больших — update_page_section по секциям (payload > ~10КБ падает). После записей верифицируй get_page.
