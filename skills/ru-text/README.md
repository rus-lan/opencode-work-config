# ru-text

Один скилл для русского текста с четырьмя ветками: редактура, UX-микрокопирайтинг,
перевод с английского и аудит без правки.

Собран из двух открытых скиллов без дублирования правил.
Методология: инфостиль Максима Ильяхова («Пиши, сокращай», Главред).

## Зачем

Обычный редакторский скилл знает про стоп-слова, но не знает про маркеры машинного
текста. Или наоборот: чистит «ИИ-шность», но не различает кнопку и статью. Здесь всё
в одном месте, а ветка выбирается по задаче.

Ключевое отличие от исходников: **запрет на выдуманные факты**. Правило «добавь
конкретику» без этого ограничения заставляет модель сочинять цифры. Здесь вместо
выдуманной цифры ставится плейсхолдер `[цифра: срок доставки]`, а механический eval
проверяет, что новых чисел в результате не появилось.

## Ветки

| Ветка | Когда | Что делает |
|---|---|---|
| **A. Редактура** | «отредактируй, вычисти, сократи, убери ИИ» | Пять проходов: чистка, наполнение, перестройка, тип, типографика |
| **B. UX-текст** | кнопки, ошибки, пуши, SMS, формы, модалки | Краткость, лимиты, формулы для интерфейса |
| **C. Перевод** | английский исходник, нужен русский | Черновик по смыслу, отражение, редактура, глоссарий |
| **D. Аудит** | «проверь, найди проблемы», без правки | Вердикт и список проблем с приоритетом |

## Установка

### opencode (глобально)

```bash
git clone <repo> ru-text
cp -r ru-text ~/.config/opencode/skills/ru-text
```

### opencode (в проект)

Скопировать каталог скилла в `.opencode/skills/ru-text` — скилл станет доступен
только в этом проекте.

Для других агентов (Codex, Cursor, Windsurf, Gemini CLI) — скопировать папку
в каталог скиллов соответствующего агента.

## Использование

```
ru-text Презентация за 5 минут — загрузите тему и получите готовые слайды
ru-text кнопка: отправить заявку на консультацию
ru-text переведи: Our platform allows you to have a seamless experience
ru-text проверь текст перед публикацией, не правь
ru-text путь/к/файлу.md
```

Режимы:

- `edit` — по умолчанию: текст и до пяти пунктов изменений.
- `report` — контекст, оценки до и после по четырём осям, альтернативы.
- `diff` — таблица «До | После | Почему» для коротких текстов.

Глубина: `light`, `standard`, `deep`. По умолчанию `standard`.

Если в исходнике нет фактов, скилл не выдумывает цифры и не растягивает текст общими
словами: он добавляет блок «Нужны данные» с тем, чего не хватает.

## Что внутри

```
ru-text/
  SKILL.md                    # маршрутизация, ветки, запреты, гейт
  references/
    style-core.md             # стоп-слова, оценки, канцелярит, эвфемизмы, синтаксис
    ai-markers.md             # лексические, структурные и тональные маркеры ИИ
    text-types.md             # матрица типов текста и лимиты
    typography.md             # кавычки, тире, списки, числа, «ё»
    pretentious-words.md      # 100+ пар «заумно → просто»
    anti-calques.md           # кальки, ложные друзья, глоссарий
    scoring.md                # четыре оси и чек-лист
    examples.md               # 13 примеров до/после
  evals/
    criteria.md               # 12 механических критериев
    test-cases.md             # 21 кейс по всем веткам
    score.py                  # подсчёт score
  scripts/
    lint.py                   # линтер русского текста с selftest
```

## Метрика

```bash
python3 evals/score.py evals/outputs/
```

Считается процент пройденных механических критериев. Субъективные оценки в метрику
не входят. Цель — 90% и выше. Отдельно проверяется, что модель не выдумала ни одной
цифры: это главный критерий, а не примечание.

## Линтер

```bash
python3 scripts/lint.py текст.md          # проверить файл
cat текст.md | python3 scripts/lint.py    # или stdin
python3 scripts/lint.py --json текст.md   # машинный вывод
python3 scripts/lint.py --baseline 3 ...  # допустить три нарушения
python3 scripts/lint.py --selftest        # проверить сам линтер
```

Линтер проверяет стоп-слова, канцелярит, пустые оценки, маркеры ИИ, типографику,
длину предложений, пассив, номинализации, повторы и качели синонимов. Жёсткие нарушения
дают код выхода 1, рекомендательные не валят прогон. Модальность не проверяется
намеренно: «может не пройти» — это содержание, а не стиль.

## Принципы

1. Инфостиль — навигация, а не автозамена.
2. Удалил — замени фактом или перестрой фразу.
3. Нет данных — плейсхолдер, не правдоподобная выдумка.
4. Хороший текст не переписывают.
5. Юридический и художественный текст не редактируют.
6. Тип текста важнее общего правила.
