# Context Metrics Skill

Мониторинг и отображение метрик использования контекста, лимитов и effort для текущей сессии opencode.

## Описание

Этот скилл предоставляет:
- Отображение текущего использования контекста (токены, процент)
- Показ rate limits (часовые/дневные/недельные/месячные)
- Отображение effort информации (текущий/максимальный)
- Предупреждения о приближении к лимитам
- Рекомендации по оптимизации использования

## Команды

### `/context` - Показать метрики контекста

Отображает полную информацию о текущем использовании:

```
/context
```

**Вывод:**
```
Session: <session-id>
Model: <provider>/<model>
Context Limit: 128,000 tokens
Used: 5,432 tokens (4.2%)

Rate Limits:
  - Hourly: 10,000 / 50,000 (20%)
  - Daily: 50,000 / 200,000 (25%)
  - Weekly: 200,000 / 1,000,000 (20%)
  - Monthly: 1,000,000 / 5,000,000 (20%)

Effort: high / max

Warnings:
  - Context usage is low (4.2%) - good!
  - Daily limit approaching 50% usage
```

### `/context watch` - Непрерывный мониторинг

```
/context watch [interval]
```

Непрерывно обновляет метрики с указанным интервалом (по умолчанию 30 секунд).

### `/context compact` - Сжать сессию

```
/context compact [threshold]
```

Рекомендует и выполняет сжатие сессии, если использование контекста превышает порог (по умолчанию 80%).

### `/context limits` - Показать лимиты

```
/context limits
```

Отображает все настроенные лимиты для текущей модели.

### `/context effort` - Показать effort

```
/context effort [level]
```

Показывает текущий effort или устанавливает новый уровень (если поддерживается моделью).

## Функциональность

### 1. Сбор метрик

Скилл собирает следующую информацию:
- Общее количество токенов (input + output + reasoning + cache)
- Процент использования контекстного окна
- Rate limits из конфигурации модели
- Текущий и максимальный effort
- Стоимость сессии (если доступна)

### 2. Умные предупреждения

Автоматические предупреждения при:
- Использовании контекста > 80%
- Приближении к rate limits (> 70%)
- Высоком использовании cache tokens
- Неправильном распределении input/output токенов

### 3. Рекомендации

Предлагает оптимизации:
- Сжатие сессии при высоком использовании
- Переключение на модель с большим контекстом
- Уменьшение effort для экономии токенов
- Архивация старых сообщений

## Интеграция с конфигурацией

Скилл автоматически читает конфигурацию из `opencode.json`:

```json
{
  "provider": {
    "my-provider": {
      "models": {
        "my-model": {
          "limit": {
            "context": 128000,
            "output": 8192,
            "hourly": 10000,
            "daily": 50000,
            "weekly": 200000,
            "monthly": 1000000
          },
          "effort": {
            "current": "high",
            "limit": "max"
          }
        }
      }
    }
  }
}
```

## Примеры использования

### Проверка текущего состояния
```
/context
```

### Мониторинг в реальном времени
```
/context watch 15
```

### Сжатие при необходимости
```
/context compact 75
```

### Просмотр лимитов конкретной модели
```
/context limits
```

### Изменение effort
```
/context effort medium
```

## Зависимости

- opencode.json с конфигурацией моделей и лимитов
- Доступ к API opencode для получения метрик сессии

## Настройка

Для активации скилла добавьте в `opencode.json`:

```json
{
  "skills": {
    "enabled": [
      "context-metrics"
    ]
  }
}
```

## Скрипты

### get-context-metrics.sh
Получает текущие метрики контекста из активной сессии.

### check-limits.sh
Проверяет текущее использование против настроенных лимитов.

### suggest-optimizations.sh
Анализирует использование и предлагает оптимизации.

## Ограничения

- Rate limits зависят от поддержки провайдером
- Effort доступен только для некоторых моделей
- Реальные лимиты могут отличаться от настроенных
