# holst-board-read

Пайплайн чтения доски Holst, отработанный на реальной доске. Только **чтение** —
ничего не редактировать, не двигать, не удалять.

## Когда применять

Нужно узнать, что изображено на холсте Holst: узлы, тексты, структуру (ряды,
колонки, группы), авторов и участников. Не применять для создания/правки досок.

## Выбор пути

| Ситуация | Путь |
|---|---|
| Есть членство в воркспейсе, есть URL доски или открытая вкладка | **1 — Holst MCP** |
| `PERMISSION_DENIED` от MCP, доска открыта по share-ссылке, учётка — гость | **2 — Playwright** |

Начинать всегда с пути 1: он дешевле и даёт машинно-читаемые узлы. Путь 2 — только
после гейта.

## Путь 1 — Holst MCP

Инструменты сервера (всего 10): `create_board`, `download_assets`, `export_holst`,
`get_guide`, `get_screenshot`, `import_holst`, `list_workspaces`, `resolve_board`,
`upload_assets`, `use_holst`. Инструмента «whoami» и «список досок по имени» НЕТ.

1. `resolve_board({url})` — по явному URL доски; `resolve_board()` — снимок активной
   вкладки приложения. Возвращает `boardId`; его передавать во все board-scoped вызовы.
2. `use_holst` — фасад API: `holst.board.findAll()` для инвентаризации узлов (типы,
   тексты, координаты). Дальше — точечные выборки через тот же фасад.
3. `get_screenshot` — скриншот доски.
4. `export_holst` — `.holst`-бэкап, если нужен полный офлайн-слепок.
5. `list_workspaces` — диагностика «под кем сидит приложение»: личные воркспейсы вида
   `<login>'s workspace` выдают аккаунт.

Про MCP-сервер:

- MCP = **локальный bridge** к десктоп-приложению: `type: remote`,
  `url: http://127.0.0.1:47641/mcp`. Порт держит процесс `holst-desktop-app`.
- Токен/заголовок bridge **игнорирует** (проверено: фиктивный Bearer даёт тот же
  результат) — личность берётся из сессии десктоп-приложения.
- `HOLST_MCP_TOKEN` к MCP-доступу отношения не имеет. Облачного MCP-эндпоинта у
  Holst нет (`app.holst.so/mcp` → 405, `api.holst.so/mcp` → 404, `api/*` → 403 edge).

### Ошибка-гейт: PERMISSION_DENIED (guests)

```
PERMISSION_DENIED — Holst MCP board operations are not available to guests.
Ask a workspace administrator to make you a member.
```

Значит: доска открыта по share-ссылке, а учётка в ней — гость.

Лечение (только эти два):

1. Вход в **десктопном** приложении под нужным пользователем (ручной Sign out → вход).
2. Админ добавляет учётку в участники воркспейса.

Перезапуск opencode НЕ помогает. Токены и заголовки НЕ помогают. Cookies в
`~/.config/Holst/Cookies` зашифрованы, email в открытом виде локально не хранится —
не пытаться выковырять личность оттуда. Если членства нет — идти путём 2.

## Путь 2 — Playwright (чтение по share-ссылке)

Работает для ссылок вида `https://app.holst.so/share/b/<boardId>`.

### 1. Гейт: бинарь Chromium

MCP playwright в конфиге жёстко зашит на
`--executable-path ~/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome`
(= playwright **1.63.0**). Проверить:

```bash
ls ~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome
```

Если сборки нет:

```bash
PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu24.04-x64 npx -y playwright@1.63.0 install chromium
```

~187 МБ + headless shell ~114 МБ. Без `--with-deps` — sudo не нужен. MCP подхватывает
новый бинарь без рестарта opencode.

### 2. Открыть доску

`browser_navigate` на share-URL → title `<BoardName> - Holst`.

Поверх доски появляется модалка «Добро пожаловать на доску …» с полем «Отображаемое
имя» и кнопками «Продолжить без аккаунта» / «Войти».

**НЕ логиниться, пароли не вводить.** Модалку скрыть локально через
`browser_evaluate`: `display:none` на портале модалки + снять `inert`/`aria-hidden`
с `#root`. Это меняет только клиент, серверное состояние не трогается.

### 3. Понять, что доска — canvas

Доска рендерится в `<canvas>` (обычно 2). В DOM **ноль** `[data-node-id]`,
`[class*="node"]`, `foreignObject`; `document.body.innerText` содержит только
UI-хром. Текст из DOM не вытащить — читать **визуально по скриншотам**.

### 4. Снимать иерархию кадров

- `browser_take_screenshot` общего вида (fit, ~19%).
- Затем зум/пан по областям (`browser_mouse_wheel`, перетаскивание).
- Отдельный кадр на каждую карточку/колонку (25–35%).
- Складывать в `/tmp/opencode/holst-<board>/` (MCP по умолчанию кладёт в
  `~/.playwright-mcp/`).

### 5. Прочитать содержимое с кадров

Заголовки карточек, стикеры, оценки, счётчики комментариев, имена коллабораторов
(курсоры). Для больших досок: сначала overview, потом детальные кадры. Описывать
**структурой** (ряды / колонки / группы), а не сплошным текстом.

### 6. Завершить

Ничего не редактировать на доске — только просмотр. `browser_close` в конце, если
сессия больше не нужна.

## Ловушки

- **HTTP/webfetch доску не читает.** SSR-оболочка `<div id="root"></div>`, весь рендер
  клиентский; API-роуты `/api/*` → 403 «Request forbidden by administrative rules».
  Не тратить попытки на угадывание API.
- **Закрытие окна Holst не завершает процесс** (singleton). Для реального рестарта:
  `pkill -f holst-desktop-app`, проверить `ps -eo pid,comm`, затем запустить заново
  (AppImage из `~/Applications/Holst-*.AppImage --no-sandbox`, окружение `DISPLAY`,
  `XAUTHORITY`, `DBUS_SESSION_BUS_ADDRESS`).
- `pkill -f holst-desktop-app` может совпасть с командной строкой собственного шелла
  агента — проверять через `ps -eo pid,comm`, а не по факту совпадения шаблона.
- **Сессия приложения живёт в профиле:** рестарт НЕ переключает учётку. Нужен ручной
  Sign out → вход; пароли вводит пользователь.
- Скриншоты в headless — реальные пиксели; OCR не обязателен, читать визуально по
  изображению.
- Не путать с другими MCP: `subCalendarId` и подобное к Holst не относится.

## Чек-лист

1. `resolve_board` → есть `boardId`?
2. `use_holst` → читается? Если `PERMISSION_DENIED` → путь 2.
3. Playwright: бинарь `chromium-1243` есть? Нет → install.
4. navigate → скрыть welcome-модалку → overview-скриншот.
5. Зум по областям → детальные скриншоты → прочитать и структурировать.
6. Вернуть отчёт (ниже).

## Формат отчёта

- тип доски / тема;
- количество элементов и их типы (карточки, стикеры, фреймы, связи);
- ключевые тексты по группам (ряды / колонки / кластеры);
- авторы и участники (если видны);
- пути к сохранённым скриншотам.

Если доска не прочитана — честно указать, на каком шаге остановились и почему
(гость / нет бинаря / canvas без DOM / нет доступа к URL).
