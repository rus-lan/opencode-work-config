# Исторические артефакты-источники

Здесь лежат файлы, из которых **перенесены** правила расчёта. Это не
действующие правила и не рантайм-зависимость: скрипт их не читает.

## `calculator/калькулятор критичности упрощенный.xlsx`

Исходный Excel-калькулятор экспресс-оценки критичности (8 листов; лист
«Расчет» скрытый, макросов в файле нет).

| Что | Где в файле |
|-----|-------------|
| Входы | лист «Простой - Экспресс оценка», `C2` (клиентов/час), `C3` (тип клиентов), `C4` (характер влияния), `C5` (SLA, мин) |
| Расчёт | лист «Простой - Детальная оценка», строка 5 (`E5` — баллы/час, `G5:J5` — времена наступления последствий) |
| Справочники | скрытый лист «Расчет»: `A50:B56` (коэффициенты типа клиентов), `D51:F56` (коэффициенты и категории влияния), `B9:C14` (интервалы), `D26:I29` (матрица), `B35:C39` (балл → уровень) |
| Результат | `Расчет!J33` (балл), `K33` (уровень), `C7` (итог) |

**Алгоритм перенесён в критерии** — `express_method` в
[`criteria/criticality-criteria.yaml`](../../criteria/criticality-criteria.yaml)
(`kind: documented`, `source_artifact` указывает на этот файл). Коэффициенты,
интервалы, матрица и отображение «балл → уровень» продублированы в критериях,
поэтому рантайм-зависимости от xlsx **нет**: файл можно удалить, расчёт не
изменится. Проверка переноса — `make selftest` (золотые векторы в
`scripts/fixtures/`, пересчитанные движком LibreOffice).

Отклонения скилла от поведения файла (пустой SLA, пустые входы, `MC+`,
хвостовые пробелы в enum) перечислены в
`express_method.deviations_from_artifact` и объяснены в
[08-criteria.md](../08-criteria.md#10-как-считается-экспресс-оценка).

## `calculator/example-erm.mm.png`

`example-erm.mm.png` — пример заполнения экспресс-оценки для `erm.mm`
(75528 / Сотрудники Группы / не смог узнать информацию / 240 → BC).
Скриншот заполненного листа «Простой - Экспресс оценка» исходного
калькулятора — визуальная сверка контрольного примера из
[08-criteria.md §10.2](../08-criteria.md#102-контрольный-пример).

Правила репозитория для этого каталога:

- файлы не правятся: изменение поведения расчёта делается в критериях, а
  эталонные значения — в `scripts/fixtures/`;
- ссылаться на него можно только как на источник (`source_artifact`), не как
  на исполняемый артефакт.
