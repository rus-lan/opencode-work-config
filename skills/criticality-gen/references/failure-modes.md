# Режимы отказа: criticality-gen

Таблица «симптом → причина → что делает скилл → как чинить». Симптом — то, что
видит пользователь в выводе; не «ошибка в данных», а конкретная строка.

| # | Симптом | Причина | Что делает скилл | Как чинить |
|---|---------|---------|------------------|------------|
| 1 | `нет is.yaml` / `MISSING is.yaml` | файл не создан или удалён | останавливается до `prepare`; не создаёт файл молча | `make init`; заполнить список ИС в `is.yaml` (образец — `templates/is.example.yaml`); данные карточки — `ssot_get` → `ssot-import` |
| 2 | `ssot_get` вернул `auth_required` / ошибку MCP | MCP `ssot-mcp` не запущен или истекла SSO-сессия | останавливается: без снимка карточки нечего собирать в `INFORMATION.yaml`; `ssot_status` в выводе — не `authorized` | перезапустить `ssot-mcp`, пройти SSO, повторить `ssot_get` → `make ssot-import IS=<код> ENTITY_JSON=<файл>` |
| 3 | `нет данных ssot_get (снимок не импортирован)` | `ssot-import` не запускался или `ssot_snapshot` пуст | `prepare`/`start` останавливаются с подсказкой импортировать снимок | `ssot_get` → `make ssot-import IS=<код> ENTITY_JSON=<файл\|->` |
| 4 | `INFORMATION.yaml` не разбирается (`YAML error`, `не битый`) | ручная правка сломала отступы, табы, кавычки; смешаны секции | `prepare` печатает `ERROR` и **не перезаписывает файл** (ручные секции сохраняются); `check`/`start` останавливаются с указанием файла | восстановить из `git`, поправить отступы (пробелы, не табы), проверить `make check`; перезапись — только `make prepare-apply FORCE_OVERWRITE=1` |
| 5 | `blocking 1/3`, `сценарий сложный`, `вердикт BLOCKED` | блокирующий вход выбранного сценария не заполнен или имеет `status: missing`; неполный сложный набор | останавливается, пишет `DATA-REQUIREMENTS.md`/`.yaml` со списком отсутствующих входов, `source_hint` и адресатами; фолбэк на простой сценарий не предлагает | отдать лист адресатам, вернуть заполненным, `make enrich-apply IS=...`, затем `make check`; если сложную оценку собрать нельзя — осознанно очистить сложный набор целиком (тогда простой сценарий, `status: preliminary`) |
| 5a | `значения вне допустимых множеств: ...` | `cia` не из `low/medium/high`, ось вне 0..4, `bucket` не из `time_buckets.order`, `object_sla` < 0, `peak_hour_load` ≤ 0, enum-поле не из списка | `check` и `start` дают `BLOCKED` с точной причиной и ожидаемым набором; трейсбека нет | привести значения к допустимым в `INFORMATION.yaml`; списки — в `criteria/criticality-criteria.yaml` и `docs/03-fields.md` |
| 6 | `статус: CONFLICT` в `GENERATION.md` / `conflicts` в паспорте | расчёт ≠ `identity.criticality_ssot` (`calculation vs ssot`) или `catalog.criticality` ≠ SSoT (`ssot vs catalog`) | не перезаписывает молча: пишет оба конфликта в `conflicts`, `GENERATION.md` и §1/§7 `CRITICALITY.md`, оставляет оба значения | подтвердить верное значение у TL / SRE, обновить `INFORMATION.yaml` или карточку SSoT, перегенерировать |
| 7 | `статус: CONFLICT — существующие файлы отличаются от сгенерированных` + `файлы не изменены. Перезаписать: --force` | `start-apply` без `FORCE=1`; защита от перезаписи | печатает список отличающихся файлов (и diff при `DIFF=1`), **ничего не пишет**, ненулевой код (CLI → 1, make → 2) | `make start IS=erm.mm DIFF=1` → просмотреть diff → `make start-apply IS=erm.mm FORCE=1` |
| 8 | `BLOCKED: невалидный enum ...` / значение вне множества | в `INFORMATION.yaml` свободный текст вместо `consumers_type` / `outage_impact` или число вне диапазона; проверяется в гейте до рендера | останавливает `check`/`start`, печатает полный список допустимых значений из `enum_selection`, файлы не изменены | привести к enum из `criteria/criticality-criteria.yaml`; см. `docs/03-fields.md` |
| 9 | `PyYAML: нет` / YAML разобран частично | PyYAML не установлен, работает мини-парсер | продолжает, но предупреждает; сложные конструкции (якоря, многострочные скаляры) могут не разобраться | `python3 -m pip install pyyaml`; либо упростить YAML; проверить `make check` |
| 10 | GitLab MCP `404 Not Found` | неверный путь проекта, нет прав, репозиторий переименован | не блокирует артефакты: оставляет ссылку пустой и помечает `missing` | проверить `gitRepository` в `ssot/.../components.yaml`, права токена; вписать ссылку вручную с `source: {type: gitlab, ref: ...}` |
| 11 | `TemplateError: шаблон ..., строка N: неизвестный путь` | в шаблоне путь, которого нет в контексте рендера; или поле стало `null` без фильтра | останавливает `start`, артефакты не записаны | добавить в шаблон `\| or_missing` / `\| default` / `\| yaml`; либо добавить путь в `build_render_context()`; `make selftest` |
| 12 | `status: incomplete` в `score` | гейт `evaluate_gate` вернул `BLOCKED` (нет blocking-входов сценария или значение вне множества) или явные параметры (`--axes`/`--cia`/`--express`) заданы неполно | возвращает `incomplete` и список недостающих критериев, уровень не выдумывает, без трейсбека | вернуться в фазу `enrich`, добрать blocking-входы, повторить `make check` |
| 13 | `validate`: ERROR по паспорту | нарушена схема: нет обязательного поля, невалидный enum, битый YAML | помечает паспорт как блокер сдачи; `start` для этой ИС не считается успешным | исправить источник (`INFORMATION.yaml`) и перегенерировать; не править паспорт руками (R2) |
| 14 | `Jira MCP 401/403` при `--create-task` | истёк токен или нет прав на проект | не создаёт задачу, отдаёт `actions/jira-task.md` как ручной пакет | обновить токен MCP; создать задачу по action-пакету и вписать ключ в `INFORMATION.yaml` |
| 15 | `RocketChat MCP недоступен` | MCP RocketChat в системе отсутствует всегда | не пытается отправить: формирует текст в `actions/rocketchat-message.md` | человек копирует текст в `#Criticality_assessment`; ссылки и поля уже заполнены |
| 16 | Два прогона дают разный `sha1sum` | в шаблон попала текущая дата, нестабильный порядок коллекции, случайный id, признак переоценки вычислен по уже созданному паспорту | считает детерминизм нарушенным, diff не является сигналом | убрать `now()` из шаблона, дату брать только из `--date`, сортировать коллекции, `reassessment` — только из `catalog.review_date`/`approve_link`/`history`; повторить проверку |
| 17 | `enrich`: `нет source` / `status не confirmed` / `значение вне множества` | лист заполнен без источника, без подтверждения или недопустимым значением | возвращает код 1, перечисляет отклонённые записи; `INFORMATION.yaml` не меняется ни на байт | получить подтверждение у адресата, указать `source: {type, ref}` и `status: confirmed`, повторить `make enrich-apply IS=...` |
| 18 | `DATA-REQUIREMENTS.*` не создан при `BLOCKED` | гейт запущен с `--no-requirements` (`NO_REQUIREMENTS=1`) или у ИС нет каталога | ничего не пишет — это осознанный флаг, а не сбой | убрать `NO_REQUIREMENTS=1`; при отсутствии каталога — `make scaffold` |
| 19 | ИС пропала из работы, вердикт `SKIPPED` | `excluded: true` + `reason` в `catalog.yaml` (общее) или `is.yaml` (локально) | не считает, не блокирует остальные ИС, печатает `SKIPPED` с источником в таблице и итоге | если исключение снято — `make include IS=... [EXCLUDE_SCOPE=catalog]`; если нет — решение об исключении остаётся |
| 19a | `RESEARCH-PLAN.md` не создан при `BLOCKED` | `collect` не запускался, либо у ИС нет каталога, либо ИС исключена (`SKIPPED`) | план не пишется — это ожидаемое поведение, лист требований при этом на месте | `make collect-apply IS=...`; при отсутствии каталога — `make scaffold`; исключённую ИС вернуть `make include IS=...` |
| 19b | `Rate limit exceeded … Current limit: 30, Remaining: 0` | лимит Confluence MCP на общий ключ, делится между агентами; `reset` в ответе завышен | сбор останавливается на этой странице, план остаётся валидным | батчи ≤10 страниц с паузами, пауза 1–2 мин и повтор; не отказываться от сбора и не заполнять значение догадкой |
| 19c | `confluence_get_page` вернул пустой `content.value` | страница в новом редакторе (ADF); текст в истории версий, а не в текущем body | страница считается непрочитанной, значение не выставляется | `confluence_get_page_history(page_id, version)` — история отдаёт полный текст; зафиксировать `page_id` и версию |
| 19d | `Request timed out` от `grafana_query_prometheus` | тяжёлый запрос (`max_over_time` на 30d с шагом 5m) | нагрузка не получена; `peak_hour_load` — blocking-вход, поэтому простой сценарий остаётся `BLOCKED` | уменьшить разрешение подзапроса (`[30d:15m]`) или сузить окно; взять 7d и отметить окно в `source.ref` |
| 19e | `grafana_search_dashboards` вернул дашборды всех папок | параметр `folderUids`/`folderUIDs` игнорируется сервером | план указывает искать дашборд по имени, а не по папке | фильтровать результат на клиенте по uid папки E001 (`feuw533xc1hq8c`); uid брать из ссылки дашборда |
| 19f | `404` / `datasource not found` при запросе панели | панель ссылается на удалённый datasource | значение не подставляется | взять datasource из ответа панели; при 404 — другая панель/дашборд; зафиксировать, что источник недоступен |
| 20 | `Permission denied (publickey)` / `could not read Username` при клонировании сервиса | нет ssh-ключа или прав на репозиторий `git_repository` | фиксирует `clone_error` в `SERVICE-FINDINGS.md`, остальные сервисы анализирует, ИС не блокирует | запросить доступ у владельца репозитория; проверить `git ls-remote <url> HEAD`; повторить `make services-apply IS=...` |
| 21 | `SERVICE-FINDINGS.md` не создан | у ИС нет `components[]` с `git_repository`, нет папки `is/IS/`, либо ИС исключена (`SKIPPED`) | печатает причину по ИС, файл не пишет | `make prepare-apply` (компоненты из SSoT), `make include IS=...` для исключённой; при отсутствии репозиториев в `components.yaml` — запрос в SSoT |
| 22 | В §7 «Не найдено»: `нет docs/`, `нет openspec/`, `нет SLO-конфигурации` | в клоне сервиса этих каталогов/файлов действительно нет | не выдумывает документацию: перечисляет отсутствующее, значения берутся из Confluence/Grafana | это факт, а не сбой; зафиксировать в отчёте и собрать основание из Confluence; при необходимости запросить документацию у команды сервиса |
| 23 | В «Нормативах» строка из `go.sum` / `package-lock.json` / теста | ключевое слово совпало внутри слова (`translator` → SLA) или сканировался lock-файл | ложные находки отсекаются: аббревиатуры ищутся по границам слова, lock-файлы, минификаты и тесты не читаются | если шум остался — уточнить `SERVICE_KEYWORDS` / `SERVICE_BASIS_RULES`, прогнать `make selftest` (проверки `services(norms)`) |
| 24 | `инвариант этапа services нарушен: внутри apps/ разрешён только git` | попытка запустить сборку, тест или скрипт из клона | команда падает **до** запуска процесса; в клоне ничего не меняется | убрать вызов: клон только читается, единственный процесс — `git` (R12); значение подтверждает человек, а не запуск |
| 25 | `ssot_form_save`: `save_not_observed` / `awaiting_approvers` | форма не вернула `mrUrl` (сохранение не наблюдалось) или MR ждёт апрувов | `ssot-record` пишет статус, а не выдумывает ссылку; при `save_not_observed` `.ssot/<код>-MR.url` не создаётся | повторить `ssot_form_save` и передать ответ в `ssot-record`; при `awaiting_approvers` — собрать апрувы, затем `ssot_mr_approve(confirm: true)` |

## Как читать эту таблицу

1. Найти строку по симптому из вывода — не по догадке.
2. Выполнить «что делает скилл»: это уже произошло, повторять не нужно.
3. Выполнить «как чинить» до конца, затем повторить фазу с её гейта.

Если симптома в таблице нет — это новый режим отказа: остановиться, зафиксировать
вывод команды и добавить строку в этот файл. Не «обходить» незнакомую ошибку
правкой сгенерированного артефакта.
