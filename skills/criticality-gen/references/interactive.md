# Интерактивный слой: как спрашивать человека (`ask`)

`check` говорит **что** не так (`BLOCKED`, не хватает N входов),
`DATA-REQUIREMENTS.md` — **где** искать, `collect` и `services` — **каким
маршрутом**. Дальше начинался разрыв: агент сам решал, **что именно** спросить
у человека, и мог спросить не то, неполно или на другом языке.

`ask` этот разрыв закрывает: он отдаёт готовый план вопросов — по вопросу на
каждый незакрытый вход, с дословно раскрытым enum, найденными кандидатами и их
провенансом, одинаковым набором вариантов ответа и последствием «ответа нет».

Правило одно и то же на всех шагах: **агент не выдумывает значения и не
угадывает молча**. Нет данных — есть вопрос; нет ответа — вход остаётся
незакрытым, ИС остаётся `BLOCKED`, а не получает «примерную» оценку (R1, R3, R10).

## Когда запускать

Строго между `services-apply` и `enrich`:

```text
check (BLOCKED) → collect-apply → сбор → services-apply → ask → ответы → enrich-apply → check
```

| Условие | Действие |
|---------|----------|
| `check` вернул `BLOCKED`, `RESEARCH-PLAN.md` и `SERVICE-FINDINGS.md` уже есть, `ASK.md` нет | `make ask IS=<код>` |
| Вопросы заданы, ответы получены | `make ask-answers IS=<код> ANSWERS=<файл>` |
| `ask-answers` принял значения | `make enrich-apply IS=<код>` → `make check IS=<код>` |
| `ask` не находит кандидатов ни по одному входу | всё равно спросить: маршрут «Где взять» в вопросе — это и есть инструкция человеку |
| Данных нет и взять их негде | `make exclude IS=<код> REASON="<причина>"` (вариант «Исключить ИС из расчёта») |

Подсказка `next_step()` ведёт сюда сама: после `services-apply` при `BLOCKED`
она печатает `Следующий шаг: make ask IS=<код> — гейт BLOCKED, плана вопросов
нет (ASK.md)`. Пока `ASK.md` нет, `enrich` не предлагается.

## Как задавать вопросы

1. **Соберите план машинной формы** — один вызов на все вопросы:

   ```bash
   make ask IS=<код> JSON=1
   ```

   На stdout — JSON-массив, по элементу на вход (служебные `WARN` идут в
   `stderr`, поэтому JSON остаётся валидным):

   ```json
   [
     {
       "input": "peak_hour_load",
       "title": "Пиковая нагрузка",
       "role": "blocking",
       "method": "express",
       "type": "int",
       "allowed": ["целое > 0"],
       "candidates": [
         {"value": 44168, "label": "Пик запросов GraphQL-шлюза", "confidence": "strong",
          "source": {"type": "grafana", "ref": "dashboard uid=<uid>, panel <id>, expr: …"}}
       ],
       "options": [
         {"number": 1, "kind": "candidate", "text": "Взять кандидат 1 — 44168 запросов/час (уверенность: strong)"},
         {"number": 2, "kind": "manual", "text": "Ввести своё значение — значение + source: {type, ref}"},
         {"number": 3, "kind": "source_url", "text": "Указать ссылку на страницу или дерево страниц — пришлите ссылку, я прочитаю и извлеку значение (нужна дословная цитата)"},
         {"number": 4, "kind": "freeform", "text": "Ввести произвольный текст с данными — напишите как есть, я разберу и зафиксирую цитату"},
         {"number": 5, "kind": "waive", "text": "Пропустить и продолжить без этих данных — оценка будет предварительной (диапазон), вход останется неподтверждённым (status: waived, R17)"},
         {"number": 6, "kind": "exclude", "text": "Исключить ИС из расчёта — make exclude IS=<код> REASON=\"<причина>\""}
       ]
     }
   ]
   ```

   `kind` — машинный вид ответа; агент переносит его в опцию `question`
   один-к-одному, не додумывая текст и не меняя порядок. `number` — тот же
   номер, что видит человек.

2. **Один элемент — один вопрос.** Не склеивайте входы в один вопрос и не
   задавайте вопрос «пачкой»: у каждого входа своё допустимое множество, свой
   адресат (`whom`) и своё последствие отсутствия ответа.

3. **Формулировка вопроса** — из элемента, по-русски:

   - заголовок: `<title> (<input>)` + роль: `blocking` или `advisory`;
   - тело: «Что это» (`definition` из `ASK.md`), «Допустимые значения»
     (`allowed` — для enum перечислить **все** значения дословно, нумерованно),
     «Где взять» (`where`), «У кого» (`whom`);
   - варианты: `options` как есть, в фиксированном порядке — кандидаты с
     провенансом → «ввести своё значение» → «указать ссылку на страницу» →
     «ввести произвольный текст» → «пропустить» (`waive` у blocking-входа,
     `deferred` у advisory) → «исключить ИС»;
   - последствие: «если ответа нет» — `blocking` оставит ИС в `BLOCKED`;
     выбранный `waive` закроет вход, но оценка станет предварительной
     (диапазон, R17); `advisory` оставит паспорт неполным.

4. **Всегда оставляйте человеку выход.** Даже если найден `strong`-кандидат,
   в списке обязательны «ввести своё значение» и «пропустить» (`waive` у
   blocking-входа — с записанной причиной и допущением): кандидат —
   предложение, а не решение за человека.

5. **Перед вопросами покажите кандидатов с источником.** Человек должен видеть,
   откуда взялось число: `dashboard uid`, `page_id`, файл SSoT или логин
   эксперта. Кандидат без источника помечен `weak` и подаётся как основание,
   а не как значение.

6. **Не подсказывайте ответ.** Запрещено: «обычно здесь 10000», «по аналогии с
   другой ИС возьмём 60 минут», «скорее всего внутренние клиенты». Значение
   либо есть у человека/в источнике, либо вход остаётся незакрытым.

## Язык ответов — только русский (R16)

- Все вопросы, варианты и сообщения — на русском. Значения enum — дословно из
  `criteria/criticality-criteria.yaml` (они русские).
- **Ответы принимаются только на русском.** Ответ на другом языке не
  превращается в значение входа. Если человек ответил по-английски (или
  смесью), **переспросите по-русски** — не переводите молча: перевод — это
  интерпретация, а интерпретация входа запрещена (R1).
- Латиница допустима только там, где это идентификатор: `page_id`, uid
  дашборда, PromQL, ключ Jira/MR, имя файла или сервиса, логин, значение enum
  внешней системы.

## Как зафиксировать ответы

1. **Записать кандидатов** (если их нашёл агент) — `is/<код>/CANDIDATES.yaml`
   по форме `templates/CANDIDATES.yaml`. Значение обязано быть допустимым для
   входа; `confidence: strong` требует `source: {type, ref}` — иначе `ask`
   напечатает `WARN` и понизит до `weak`. Поле `is:` (код ИС) проверяется при
   чтении: файл чужой ИС не подмешивается — `ask` печатает `WARN` и кандидатов
   не читает.

   **Основание без значения** — законная запись, а не пропуск: `value: null`
   означает «факт найден, числового/дословного значения нет» (например «RTO —
   часы, но нормативного SLA в минутах нет»). Такой кандидат показывается в
   плане как **кандидат-основание**: `choice: candidate` по нему отклоняется
   (`кандидат N не содержит значения (основание)`), а человек пишет
   `choice: manual` и опирается на найденный факт. `confidence: strong` у
   основания понижается до `weak` с `WARN` — основание сильным не бывает.

2. **Записать ответы** — `is/<код>/ANSWERS.yaml` по форме
   `templates/ANSWERS.yaml`:

   ```yaml
   is: <код>              # код ИС: проверяется при приёме ответов
   answers:
     peak_hour_load:
       choice: candidate      # candidate | manual | source_url | freeform | waive | deferred | exclude
       candidate: 1           # номер из «Найденные кандидаты» (с 1)
     consumers_type:
       choice: manual
       value: 'Сотрудники компаний Группы (Внутренние клиенты)'
       source: {type: confluence, ref: 'page_id=<id>, раздел «Пользователи ИС»'}
     object_sla:
       choice: source_url     # человек дал ссылку на страницу
       source_url: 'https://space.samokat.ru/pages/viewpage.action?pageId=<id>'
       extracted:
         value: 240
         quote: 'SLA решения 4h'
     time_to_impact:
       choice: freeform       # человек написал данные текстом
       text: 'Последствия наступают через 2–3 часа, подтвердил SRE'
       extracted:
         value: '1-12h'
         quote: 'последствия через 2–3 часа'
       source: {type: manual, ref: 'SRE: Иванов, сессия <дата>'}
     cia:
       choice: waive          # осознанный отказ от данных (R17)
       reason: 'ИБ не дала оценки C/I/A до срока'
       fallback: {mode: assume_worst}
   excluded:
     reason: null
   ```

   `is:` — защита от подмены: `ANSWERS.yaml` другой ИС не применяется
   (`ERROR: ANSWERS.yaml принадлежит ИС '<x>', а запрошена '<y>' — ответы не
   приняты`, код 2, лист не тронут). Поля `status` в ответах нет — `confirmed`
   проставляется автоматически (`waived` — для `waive`). `decided_by`/`date`
   отказа берутся **у самого входа** (`answers.<вход>.decided_by` /
   `answers.<вход>.date`), затем из `answers.decided_by` / файла, иначе
   «пользователь» и дата прогона: решение конкретного человека не должно
   теряться за файловым значением.
   `excluded.reason` и непустые `answers` в одном файле несовместимы (код 2):
   исключение и приём ответов — два прогона.

3. **Принять ответы**:

   ```bash
   make ask-answers IS=<код> ANSWERS=is/<код>/ANSWERS.yaml
   ```

   Что происходит: значения проверяются теми же валидаторами, что гейт (enum
   дословно, целое в диапазоне, корзина времени, полный набор осей/CIA), и
   **принятые** попадают в `is/<код>/DATA-REQUIREMENTS.yaml` со
   `status: confirmed`. `INFORMATION.yaml` не меняется ни на байт: единственный
   писатель — `enrich-apply` (инвариант «факт-или-null»).

   **Составные входы** (`axes_scores`, `cia`) пишутся под-осями — так, как их
   ждёт `enrich`:

   ```yaml
   axes_scores:
     value:            # в ANSWERS.yaml — value: {legal: 0, ...}
       legal: 0
       economic: 0
       reputational: 1
       client: 1
     source: {type: manual, ref: '...'}
     status: confirmed
   cia:
     value:
       c: high
       i: medium
       a: medium
   ```

   После записи лист перечитывается и каждый принятый вход прогоняется теми же
   валидаторами, что `enrich`. Если значение не легло в лист в пригодной для
   `enrich` форме — `ERROR: вход <имя> принят, но значение не записано — это
   дефект инструмента`, код `1`, лист возвращается в состояние до записи.
   «Принято» печатается только после этой проверки: молчаливая потеря значения
   (например, `value: null` у составного входа) невозможна.

   | `choice` | Что требует | Что делает |
   |----------|-------------|-----------|
   | `candidate` | `candidate: <номер>` | берёт значение и **наследует `source`** кандидата; кандидат-основание (`value: null`) отклоняется — по нему нужен `manual` |
   | `manual` | `value` + **обязательный** `source` | пишет своё значение с указанным источником |
   | `source_url` | `source_url` (http/https) + `extracted {value, quote}` | берёт извлечённое значение; тип `confluence` (`{type: confluence, ref: 'page_id=<id>; «<цитата>»'}`) выдаётся только для URL с хоста Confluence из `criteria.external_refs.base_url` (по умолчанию `space.samokat.ru`); чужой хост с `pageId=` — `manual` с полным URL и цитатой. Креды (`user:pass@`) из URL вырезаются. Без дословной цитаты ответ отклоняется: значение без цитаты неотличимо от догадки |
   | `freeform` | `text` + `extracted {value, quote}` + **обязательный** `source` | берёт значение из свободного текста человека; цитата дописывается в `source.ref` (`'<ref>; «<цитата>»'`), как и у `source_url` |
   | `waive` | `reason` (>= 10 символов) + `fallback.mode` (`assume_worst` \| `assume_best` \| `assume_value`; у `assume_value` — ещё `fallback.value`) | **закрывает** вход без значения: `value: null`, `source: null`, `status: waived`, блок `waive` едет в лист и в `INFORMATION.yaml`; гейт считает вход закрытым, расчёт становится предварительным (диапазон, R17) |
   | `deferred` | — | не трогает вход; `blocking` оставит ИС в `BLOCKED` (для blocking-входа это не отказ: отказ — только `waive`) |
   | `exclude` | `reason` (в ответе, в `excluded.reason` или `--reason`) | исключает ИС из расчёта (`is.yaml`; `--scope catalog` — в реестр) |

   Коды возврата: `0` — все ответы приняты и значения проверены в листе; `1` —
   хотя бы один ответ отклонён (тогда не записывается **ничего**, причины
   названы) **или** принятое значение не пережило запись (дефект инструмента,
   лист откачен); `2` — ошибка аргументов или файла: нет `--answers`, файл чужой
   ИС (`is:`), файл не читается, в нём одновременно исключение и ответы.

4. **Записать в `INFORMATION.yaml` и повторить гейт**:

   ```bash
   make enrich-apply IS=<код>
   make check IS=<код>
   ```

5. **Проверить, что значения не потерялись.** `enrich-apply` печатает остаток
   листа и вердикт гейта. Если входов не осталось — лист удаляется, а `check`
   печатает `OK`, и конвейер идёт дальше (`score` → `start`).

## Разобранный пример: `peak_hour_load`

**Ситуация.** `make check IS=opercrm.smkt` → `BLOCKED`, не хватает
`peak_hour_load`, `consumers_type`, `outage_impact`, `object_sla`.

**1. Сбор.** Агент идёт по `RESEARCH-PLAN.md`: панель трафика шлюза в Grafana
(папка продукта E001) и запрос вида
`sum(increase(graphql_queries_responded{namespace="opercrm"}[1h]))` за 30 дней.
Находит пик и записывает кандидата в `CANDIDATES.yaml`:

```yaml
candidates:
  peak_hour_load:
    - value: 44168
      unit: запросов/час
      label: "Пик запросов GraphQL-шлюза за час, окно 30 дней"
      confidence: strong
      source:
        type: grafana
        ref: 'dashboard uid=<uid>, panel <id>, datasource uid=<uid>, expr: sum(increase(graphql_queries_responded{namespace="opercrm"}[1h])), окно 30d'
```

**2. Вопрос.** `make ask IS=opercrm.smkt JSON=1` даёт элемент с кандидатом и
опциями. Агент задаёт один вопрос:

> **Пиковая нагрузка (`peak_hour_load`)** — роль `blocking`, метод `express`.
> Что это: сколько клиентов или транзакций обслуживается за час пиковой
> нагрузки; целое число, единица — клиентов/час.
> Допустимые значения: 1) целое > 0.
> Где взять: Grafana, папка продукта E001 → подпапка ИС → панели трафика шлюза;
> вторично — Confluence (страницы трафика/RPS/QPS).
> Найдено: **44 168 запросов/час** — пик GraphQL-шлюза за час, окно 30 дней
> (уверенность: strong; источник: grafana, dashboard uid=<uid>, panel <id>).
> Варианты: 1) взять кандидат 1; 2) ввести своё значение; 3) указать ссылку
> на страницу — пришлите ссылку и дословную цитату; 4) ввести произвольный
> текст с данными; 5) пропустить и продолжить без этих данных — оценка будет
> предварительной (`status: waived`, R17); 6) исключить ИС из расчёта.
> Если ответа нет: гейт остаётся `BLOCKED`, расчёт уровня не выполняется.

**3. Ответ человека.** «Да, 44 168 запросов в час, панель верная» →
`ANSWERS.yaml`:

```yaml
answers:
  peak_hour_load:
    choice: candidate
    candidate: 1
```

**4. Приём.**

```bash
make ask-answers IS=opercrm.smkt ANSWERS=is/opercrm.smkt/ANSWERS.yaml
# Принято: peak_hour_load (1). Отложено: 0. Отклонено: 0.
# Лист обновлён: is/opercrm.smkt/DATA-REQUIREMENTS.yaml
```

`DATA-REQUIREMENTS.yaml` теперь содержит `value: 44168`, `unit: запросов/час` и
`source` кандидата (наследован), `status: confirmed`; `INFORMATION.yaml` не
изменён.

**5. Запись и гейт.**

```bash
make enrich-apply IS=opercrm.smkt   # value уходит в criteria_inputs
make check IS=opercrm.smkt          # осталось 3 входа — BLOCKED (ожидаемо)
```

**6. Если ответа нет.** Человек говорит «не знаю, панель не нашёл» → вариант
«оставить пустым» (`choice: deferred`). Вход остаётся в
`DATA-REQUIREMENTS.yaml`, ИС остаётся `BLOCKED` — это корректный результат, а не
повод подставить число «по аналогии».

## Разобранный пример: отказ от данных (`waive`, R17)

**Ситуация.** `make check` → `BLOCKED`, не хватает `cia`. ИБ говорит: «оценки
C/I/A не будет, решайте без нас». Это не «оставить пустым» и не повод вписать
`medium` «по аналогии» — это осознанный отказ, который надо записать.

**1. Ответ человека.** `ANSWERS.yaml`:

```yaml
answers:
  cia:
    choice: waive
    reason: 'ИБ не дала оценки C/I/A до срока'
    fallback: {mode: assume_worst}
```

`reason` — обязательная проверяемая причина (>= 10 символов); `fallback.mode` —
режим допущения: `assume_worst` (консервативно — максимум диапазона),
`assume_best` (минимум) или `assume_value` (конкретное значение, тогда диапазон
из одного уровня).

**2. Приём.** `make ask-answers` пишет в лист `value: null`, `source: null`,
`status: waived` и блок `waive {reason, decided_by, date, fallback}`.
`make enrich-apply` переносит отказ в `INFORMATION.yaml`; гейт считает вход
закрытым и печатает `OK`, но `provisional: true`.

**3. Расчёт.** `make score` перебирает домен допустимых значений входа (для
`cia` — все сочетания low/medium/high), печатает диапазон и допущение:

```text
⚠ Оценка предварительная: не подтверждены входы
  - cia: ИБ не дала оценки C/I/A до срока (допущение: худший случай (максимум диапазона))
  диапазон уровня: Business operational – Mission critical
  в паспорт записан: Mission critical — консервативная оценка по режиму допущения
```

**4. Артефакты.** `CRITICALITY.md` получает блок «⚠ Оценка предварительная» с
таблицей «вход → причина → допущение» и диапазоном, `GENERATION.md` — строку
«Предварительная оценка», `INDEX.md` — пометку `(предв.)`, публикация — одну
строку о предварительности. Паспорт остаётся каноническим (новых ключей нет):
в `object_criticality_estimation` идёт консервативный уровень по допущению.

**5. Если домен не перечислим** (свободный текст, ссылка, неизвестный enum) —
`ERROR` с просьбой подтвердить значение или указать
`fallback.mode: assume_value` + `value`. Молчаливая догадка запрещена: отказ
не должен превращаться в «примерно».

## Чего не делать

- Не задавать вопрос по входу, которого нет в плане: набор незакрытых входов
  считает гейт, а не агент.
- Не пропускать `ask` «потому что и так понятно»: без `ASK.md` подсказка
  следующего шага не пустит к `enrich`, а человек не увидит провенанс.
- Не переводить ответ молча и не «уточнять» enum своими словами: значение —
  дословно из `enum_selection`.
- Не писать в `INFORMATION.yaml` в обход `enrich-apply` — даже «на минутку»,
  чтобы проверить расчёт: расчёт проверяется `score`, а запись — `enrich`.
- Не оформлять `exclude` без причины: причина — часть паспорта и аудита (R11).
- Не считать `strong`-кандидата подтверждённым значением: подтверждает человек,
  `ask-answers` только фиксирует его выбор.
- Не выдавать `waive` за подтверждённое значение: отказ закрывает вход, но
  оценка обязана остаться предварительной (диапазон + пометка в артефактах).
  `deferred` у blocking-входа отказом не является — ИС останется `BLOCKED`.
